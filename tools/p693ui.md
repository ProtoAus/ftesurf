# P693 — profile time seeks, editor wheel, posed entity/clip faces

## Behavior

- Any part of a profile time's row opens its map/track/leg/tier/style board near
  that rank, with the exact identity/time highlighted. The compact board profile
  uses the same handoff. Fetch the neighborhood directly rather than paging a
  thousand rows first. Earlier/top and normal next-page scrolling retain valid
  offsets. Display names are not identities; both eight-character compact marks
  and twelve-character profile handles work. Legacy five-field browsing works.
- Mouse2 switches zone-editor look/window ownership. Look-mode placement keeps
  Mouse2 as its existing back/cancel action. Jump binds, including wheel and
  space, no longer switch mouse ownership; the wheel over the panel scrolls two
  list rows per step. Other panels and text-field held-key ownership stay ahead
  of the editor toggle. `zone_edit status` reports first list row.
- ent_view publishes brush poses and teleport ids. Native hull faces are placed
  with map entity origin/angles; teleport faces are red ordered dither, with a
  denser hover. World PLAYERCLIP/MONSTERCLIP hulls also draw by default. Turn off
  only that extra overlay with `ent_view_clips 0`, restore with `1`. Range follows
  `ent_view_dist`. Turning off the viewer clears its publications. Explicit
  `r_showbrushes` settings take precedence and are never rewritten. Collision,
  movement, timer/evidence and backend behavior are unchanged.

## Limits and delivery

A time moved outside the cached rank neighborhood or removed from the board is
not guessed from a same-name row: show the nearby ranks and a notice. Brush data
must survive in Q2/Q3/VBSP hulls; arbitrary nodraw surfaces and static-prop mesh
collision are not clip brushes. Existing in-view density limits remain. CPU
rotation/nonfinite checks are not a separate rotated-map GPU screenshot. GPU
acceptance here is Windows OpenGL, not Linux. No QC Build/public version bump or
release-feed change. Commit, version-stamped build, push and destination/live
verification are separate states; deployment provenance belongs in AGENT_NOTES
and the owned receipt rather than being inferred from source acceptance.
