# Entity gap census, 8 Nov 2026 (ftesurf-3a): what the maps use that the game does not do

Lex: "do a search of all the maps for missing entities/functions we are missing to be added for next release".

Tool: `python -B tools/census/entgap.py --qc . --out <dir> --engine <engine tree>` over Momentum's maps folder:
2,204 maps, 0 unreadable. A class counts as handled when SSQC has a spawn function of that name, the client or
the hl2 plugin names it, or the catch-all keeps it as walk-through brushwork; an input when a server file
compares a folded input with it; an output when SV_IOOutputKnown (or a class helper, oncase01-16) names it.
Static, so every row below was then checked by grep against src/ and the plugin; "maps" = maps using it.

## Not gaps (checked; do not re-investigate)

- light_environment (1,772 maps), light_spot (41,840 ents): baked by VRAD; nothing to do at run time.
- water_lod_control (1,217): BACKLOG measured it would not help at reflect-all.
- trigger_hurt (189 maps, 1,604) + filter_damage_type (1,132): Momentum players take no damage (BACKLOG);
  their OnHurt/OnHurtPlayer outputs (10 maps here) never fire -- known.
- game_player_equip `Use` (1,472), player_weaponstrip `Strip`, weapon_*, output OnPlayerPickup (61 maps): CS
  weapons, not part of surfing.
- info_ladder (208): a nav marker; ladders are brush contents (sv_entities.qc ladder notes).
- point_servercommand / point_clientcommand (308 / 99): removed on sight, but a `Command` aimed at them is
  routed through the allow-list (SV_IODeliver).
- trigger_momentum_timer_start/stop/stage/checkpoint: no spawn function, read by name by SV_ZoneLoadFromBsp.
