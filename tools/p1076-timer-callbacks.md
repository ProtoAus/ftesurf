# P1076: recurring timer scheduled-callback lineage

## Scope

Recurring timer callbacks retain the existing VM-local player/admission lineage
of the scheduling operation. Their original native think body runs in that scope,
including recurrence and oscillator outputs. A genuinely changed deadline or an
actual disabled-to-enabled transition replaces the scheduled obligation; an
unchanged already-enabled schedule does not retarget it. Ordinary world/current
sources remain clean. The existing actual-body write checks mark affected later
attempts practice/unranked, not cancellation.

The public TimerThink function identity is preserved: existing FireTimer,
ResetTimer and RefireTime input gates compare it exactly. The original disabled
check, random interval calculation, output selection, finite counts, recurrence
and physical effects remain. Existing bank fields/primitive are reused; no new
captured field/format, native API/pin/tag, device identifier, quiet/dwell/gameplay
threshold, qcbuild, Build or release change. Published P1074/P1075 are preserved.

This is scheduled-callback ownership, NOT every contributor to persistent timer
interval/phase or other logical state across replacements. It does not retire
those contributors or inherited body/world value. Full P455/Rule8 remains OPEN;
no historical dwell proof or pending-output/global timer ban is revived.
